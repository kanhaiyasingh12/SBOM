## 4. Tooling Evaluation & Recommendations (Talking Points & Data)

### 1:  For SBOM Standard (CycloneDX vs. SPDX)

* *"I recommend CycloneDX 1.5/1.6 as our primary format because it's built for AppSec, vulnerability mapping, and native VEX. However, by using Syft, we will generate both CycloneDX and SPDX in one command so we have zero rework if a customer mandates SPDX."*


### 2:  For Generation Tool (Syft)

* *"Syft is our clear choice. It inspects container image layers faster than anything else (3-5s), handles multi-language repos, and runs identically via CLI in Azure DevOps and GitHub Actions."*

### 3: For Vulnerability Scanning (Trivy)

* *"I recommend Trivy to scan the SBOMs generated by Syft. Trivy has an official Azure DevOps extension, native `--vex` filtering to suppress false positives, and outputs standard SARIF for pipeline security tabs."*


### 4:  For VEX Management (OpenVEX)

* *"Without VEX, 85-90% of vulnerability alerts are non-exploitable noise (dead code). We should use OpenVEX (`.security/vex.json` in Git) to filter out false positives before evaluating gates, avoiding unnecessary release fire drills."*

### 5: For Central Platform (Dependency-Track)

*  *"Pipelines only scan during builds. We need OWASP Dependency-Track to continuously re-scan our deployed SBOMs every 24 hours against newly discovered zero-days without needing to rebuild or re-deploy applications."*
